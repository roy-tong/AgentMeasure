# Buyer Ledger 产品与工程审查 · 2026-10-29

## 结论

本轮实现的方向成立：本地账本、三级口径、Agent 首次适配与确定性重放，符合“轻量接入、轻量管理”的目标。但初版 62 项测试主要覆盖 happy path，尚不足以支撑真实金额结论。审查发现的问题集中在**账本粒度、估算完整性、审批执行、定价周期、修订冲销和浏览器信任边界**，不是视觉或文案微调。

本轮已优先修复会制造错误账单/错误差异的路径，并完成合成 CLI 端到端验证。产品仍处于 **pre-M1**：不能把测试通过等同于真实平台可用或客户验收完成。

## 已修复的关键问题

### 1. 金额与对账

- 原实现按 provider 汇总，能够把不同币种、不同账户相加并错误判为 matched。
- 现按 `period + provider + account + currency` 分组，报告明确显示账户与币种。
- 部分用量未计价时，保留“已计价小计”，但不生成正式 variance 或 matched/overcharge。
- `pending / undeterminable` 记录阻断确定性经济结论，输出 `review_required`。
- 已登记但未解析/待审的账期文档同样阻断旧数据 matched；parseable 导入必须明确账期。
- 文档身份包含内容、平台、类型、账户和账期；同内容零账单可跨账户导入，旧库引用可迁移。
- 不同单位的未计价数量分别列示，不再把 operation 与 token 相加。
- 每次对账原子替换账期快照，清除重跑后的陈旧结果。

### 2. 定价与账本完整性

- 价格选择校验事件日/账期有效期；同层级多个适用政策时放弃计价，不猜一个。
- 免费额度与阶梯价按计费作用域的账期总量处理，不再给每条事件重复发额度/低档价。
- `flat` 未声明按事件还是按账期收费时保持未计价，避免固定费用被重复计算。
- 政策身份包含 provider，同版本不可变；改价必须发布新版本。
- 复算只能由定价管线写入；对账复核政策适用性、标识和币种，政策歧义/失效时撤回旧估算。
- 修订链禁止分叉、跨账户、跨平台和跨币种；已被修订的旧行不可再冲销。
- Usage 全额冲销校验当前目标、账户、单位和政策，并以唯一索引防止重复冲销。
- Usage 幂等键纳入账户、Agent、项目、修订信息和稳定源行定位，减少真实事件漏算。

### 3. Agent 解析与失败恢复

- LLM 规格从“自动保存并应用”改为 `draft → 人工 approve → replay`。
- amount、quantity、unit_price、tax 只能引用源列，禁止 LLM 用 const 制造金额。
- 默认仅发送表头，不发送原始账单行；LLM 端点要求 HTTPS（localhost 除外）。
- 规则按 provider/doc_type/tier 隔离，并在应用时重验真实表头、必填字段和资料类型。
- 每份文档原子入账；中途失败整体回滚，可用同一文件重试。
- 重解析校验当前文件哈希，防止把新内容绑定到旧 SourceDocument。
- 总额从映射的金额列读取；缺币种、缺单位、非法日期、歧义数字等失败关闭。

### 4. 浏览器与用户体验

- 限制 HTTPS/allowed_hosts；context 在导航请求前拦截越源跳转，每个动作前重查当前页。
- 下载来源 URL 在保存与入账前校验；下载、截图和 period 增加路径约束，产物写入唯一 run 目录并限制大小。
- 审计目录/文件权限收紧。
- 同平台不同账户隔离浏览器 profile；登录判断不再使用 query 中的伪造 URL。
- 文档关联 run、recipe hash、audit path 和 document ID；fetch 的 0 行结果显示 needs_parse。
- 新增 `run --period --out report.md`，规则就绪后一条命令完成复算、对账与报告。

## 验证结果

- `python3 -m unittest discover -s tests -t .`：**106 项测试通过**。
- 合成 CSV 的真实 CLI 流程已运行：导入账单与用量 → 登记价格 → 复算 → 对账 → Markdown 报告。
- 重复导入返回 duplicate，未增加账单行。
- 示例：60.00 USD 账单与 60.00 USD 完整复算输出 `variance=0.00 / matched`。
- 新增 `run --period --out` 已单独做端到端运行，一次完成复算、对账和报告。
- 旧版全局 content-hash 文档库已做迁移验证：文档、行、证据与引用均映射到作用域身份。
- 配方 validate/dry-run 可运行；危险导航、路径逃逸、空审计链等已加入回归；fake Playwright 覆盖动作前越源与跨源下载阻断。

## 2026-10-29 追加：工具覆盖、双视角与 CDP

- 新增能力目录：26 个工具（10 个国内、16 个海外），买家和卖家角色都覆盖；记录计费模型、计量单位、账单来源、审计能力和验证状态。
- 目录只表示 **cataloged**。`live_bill_validated=0`；未知 provider 在覆盖报告中原样披露，不自动套用支持结论。
- 报告新增“工具支持与计量覆盖”和 `--perspective seller` 卖方视图；未计价/未关联用量被明确标为证据缺口，不声称漏收收入。
- 新增 CDP 附着：仅允许 loopback、无 query/凭据；复用配方白名单、域名/下载来源校验和同一入账管线，只创建/关闭本次页面。
- 真实 CDP 冒烟通过：本机 Chrome 156、Protocol 1.3；本地 HTTPS 合成账单下载 1 份、登记 SourceDocument 1 份、审计含 `transport=cdp`。
- `fetch --analyze` 端到端通过：CDP 下载 → 入账 → 复算/对账 → 报告（返回码 0）。
- 仍需真实平台账单后台验收；本地 HTTPS 合成页面不等于供应商 portal 适配。

## SURE 用户账单不满研究（探索性）

- 发现 1,949 → 审读 150 → 严格证据 66；买家 62 / 卖方 4；反证 7。
- 主题：credits 到期/清零 22、未预期扣费/硬上限失效 9、自动充值 8、计量不一致 6、退款受阻 5；涨价仅 2。
- 审计 9/12 通过，结论上限 exploratory：仅 3/18 vendor 有证据、地区仅 US、反证不足。
- 产品含义：增加 credits/到期/自动充值/硬上限/额度对象；不能把它们继续当作普通账单行。
- 另完成 CDP 公开 discovery 第一阶段：2,734 原始讨论 → 2,437 可用 discovery + 26 官方计费页；仅发现层，不并入 66 条严格证据。
- SURE 发现层继续扩至 **50,000 条**唯一公开记录（HN 49,090）；严格证据仍 66、审读仍 150，主审计仍 9/12。
- 50k 压力测试：H1 证据形状支持、H2 不支持（HN 内方向反转）、H3 仅支持英文源不可见、H4 降级率 71.6%、H5 仅提示；未升级 validated。
- 公开摘要：[COMPLAINTS-20261029.md](COMPLAINTS-20261029.md)。完整原始研究在工作区，未进入公开仓库。
