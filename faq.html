1. AI 账单怎么核对？

Q: AI 账单怎么核对 / AI 账单核对工具

路径分三步：① 拿到计费规则原文（按什么计费、什么算「一次」）——供应商改规则等于改价格，Zendesk 2026-08-25 修订解决量分层文档就是最近的例子；② 拿到可对账的记录（账单或用量导出）；③ 按供应商自己的规则复算，并把「能结算的行」与「算不了的行」分开列。

Verovo 的 recount 命令内置 6 家 AI 客服供应商的规则集（Intercom Fin、Zendesk、HubSpot 等），verovo recount --list-vendors 直接打印；每条规则带来源、日期和置信度等级，登记在 vendor-rules.json，网页表格与本工具永不互相矛盾（见 证据索引的供应商计费规则记分卡）。浏览器版复算不上传数据即可试。

不想自己跑？带 20–100 行脱敏样本，走 issue #6 免费任务或官网免费任务页，24 小时内首次响应，样本合格后通常 48 小时内出检查结果。

2. API 费用怎么复算？常见的坑在哪里？

Q: API 费用怎么复算 / API 账单复算工具

API 费用复算＝用原始事件记录＋公开价格把账重算一遍。坑不是玄学，2026-09 的生态审计（约 110 个仓库，2026-09-06 → 09-09，审计报告）把它们归成了五类：

  • 一条助手消息 ≠ 一行：10 个确认工具，实测多计 2×–5×（见问题 4）
  • 重发事件重复累计：5 个工具，单个会话文件 +0.5% 到 +15%
  • 缓存计费语义：9 个工具（见问题 5）
  • 价格表过期：7 个工具，内嵌价格与公开费率偏离 1.2×–5×，包括 LiteLLM 价格文件的 vendored 副本（issue #40360）
  • 会话恢复/分叉丢历史：4 个工具，实测一个会话 86% 的 token 消失（issue #1）

审计共提交 65+ 条有据发现（报告，2026-09-19），其中 45+ 条确认为计量会计 bug、23 个修复被上游合并或接受（2026-10-11 口径，全部带上游链接，见 claims 索引）。复算工具本地免费开源；20–100 行脱敏样本的人工复算检查同样免费。

4. Claude Code / Codex 的用量统计为什么会偏多？

Q: Claude Code 用量统计偏多 / Codex token 多算

两类已实证的原因（审计报告 · claims 索引）：

  • 一条消息被按多行计。Claude Code 对一条助手消息按内容块写多行 JSONL，每行带同一个 message.id 和同样的 usage；逐行累加会把「文本＋两次工具调用」的一条消息算成 3 倍。审计确认 10 个工具有此问题，实测多计 2×–5×；tokendash 的修复（PR #37，案例卡）已于 2026-09-09 被上游合并。
  • 重发事件被重复累计。Codex 在压缩、设置变更和限流刷新后会重发总量相同的 token_count 事件，朴素累加会重复计数。确认 5 个工具，实测单个会话文件 +0.5% 到 +15%（token-vision 实测 +14.97%）。

核对方法：按消息 id 去重、按事件身份去重后重算。多数被审计仓库是干净的——这不是「用量工具普遍坏掉」的判断。想让人核对一遍你自己的数据，走 issue #6。

5. 大模型 API 的缓存计费（cache pricing）容易在哪里算错？

Q: 缓存计费 / cache write 价格 / Anthropic 缓存 token 计费

乘数是精确的：5 分钟缓存写 1.25× 输入价、1 小时缓存写 2×、缓存读 0.1×；且 Anthropic 的 input_tokens 不含缓存 token，OpenAI 的含——把一套约定用在两家上会出错。审计确认 9 个工具属于此类（claims 索引）。

案例：claude-hud（审计时 27.9k star）把 1 小时缓存写按 5 分钟的 1.25× 计价，该组件低估 37.5%——对买方这是危险方向：仪表盘比实际便宜，发票却保持正确数字，差异到对账时才暴露。修复 PR #758 已被上游合并（案例卡）。注意：这是固定提交上的组件级工程误差，不是对任何用户实际账单的判断。

6. 按「解决量（resolution）」计费的 AI 客服怎么核对？

Q: Intercom Fin 价格 / Zendesk AI Agents 计费 / resolution 计费核对

  • HubSpot Breeze：USD 0.5 / 次解决 [S]——二手来源，结论携带较弱置信度。

7. AI 客服账单有异议怎么办？

Q: AI 客服账单有异议怎么办 / AI 客服计费争议

建议顺序：① 向供应商要书面的计费规则与判定依据（每行 resolution 的判定记录）；② 按规则复算，拿到一份有依据的差异清单——哪些行多计、哪些行无法判定；③ 带着清单进入供应商复核流程。Verovo 的 dispute 命令用于整理差异项。

如实说明：复算只回答「按规则应计多少」；供应商是否认可、是否退款是后续的独立事件，Verovo 不承诺供应商接受、退款或追回（见问题 10）。免费先跑一步：20–100 行脱敏样本走 issue #6 或免费任务页；企业级整单核验走 买方任务页按个案确认范围。

Q: Verovo 是什么 / Verovo 收费吗

Verovo 是面向 AI 服务采购方的开源核验项目：费用核验（收费是否符合适用约定、费用与用量能否对应）和交付核验（实际工作是否达到买方明确的业务要求）是两条独立工作流；缺证据一律标注 UNPROVABLE（无法判断），不猜。核心用户是承担 AI 支出的业务、工程和团队负责人（中文说明）。

10. Verovo 能帮我追回多收的费用吗？

Q: 能追回多收的费用吗 / 退款承诺

不能承诺。复算是算术：按供应商自己的规则算出应计多少、列出有依据的差异项。供应商是否认可、是否退款、额度是否到账，是复算之后的独立事件，每一环都需要供应商侧的动作。规则估算差额不是已追回金额（README 中文版）。

Verovo 的产出是可复核的差异清单和证据（每条带规则引用与证据哈希），供你带进供应商复核；交付验收类任务也可以在没有费用争议的情况下单独提出（买方任务页）。没有费用争议时同样可以做交付核验。
