One suspicious number. A check you can repeat.

Agent developers

Your session has repeated records, failed tools or unexpected token totals. Check what the logs actually show before changing your setup.

Tool and API providers

A retry or instrumentation change may alter reported usage. Compare attempts, logical operations and the metrics your sample supports.

Framework maintainers

Turn a reproducible discrepancy into a fixture and regression check. Keep missing evidence visible instead of filling it with a guess.

A finding is evidence for investigation. It does not by itself prove a root cause, an overcharge or customer savings.

Start with your own logs.

New to the project? First try a synthetic example. You need Python 3.9+ and a terminal on a computer. No logs or account required.

python -m pip install --upgrade agentmeasure
agentmeasure demo

Open agentmeasure-demo-report.html in the folder where you ran the command. The terminal prints the exact path. The example contains a retry chain and failed executions; these are demonstration findings, not installation failures.

Just browsing? See what an explanation looks like

The synthetic demo shows 1 retry chain containing 3 executions, and 7 failed executions. That does not prove seven bugs or seven charges. A useful next check is to inspect the first error in the longest failure run.

Read an illustrative diagnosis. To inspect your own sessions, run the CLI on the computer holding your logs.

Installation help: macOS, Linux, Windows

Use Python 3.9+. On Windows, use py instead of python if needed. On macOS/Linux, use python3 if python is unavailable.

If pip says “externally managed” or lacks permission, use a local virtual environment:

python3 -m venv .venv
.venv/bin/python -m pip install --upgrade agentmeasure
.venv/bin/agentmeasure demo

Windows PowerShell:

py -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade agentmeasure
.\.venv\Scripts\agentmeasure.exe demo

No activation required. Use the same executable path for later commands. If agentmeasure is not found, check the install environment rather than reinstalling globally with administrator privileges.

Next: inspect your own logs and prepare a shareable summary
agentmeasure check --json report.json
agentmeasure share report.json --out summary.json
agentmeasure validate summary.json

Auto-discovery prefers Codex when both runtimes have logs. For Claude Code use agentmeasure check --runtime claude --json report.json. Open the HTML report at the path printed in the terminal; keep the full JSON and HTML local. Inspect summary.json before choosing to send it. Exporting is not uploading.

No logs, an error, or an unexpected result?

No logs in the last seven days? Try agentmeasure check --all, or point to the real directory with --dir "/path/to/logs" --runtime codex (use claude for Claude Code). An empty directory produces an input error, not a clean bill of health. If a command fails, stop before running the export commands.

Healthcheck exit 0 means the report ran, even if it contains findings. Exit 2 means an input/output problem. UNPROVABLE means missing evidence, not failure or a clean result. For conformance, exit 1 means a failed or required-but-unproven invariant.

Report a reproducible tool bug with the version, command, expected behavior and a redacted error. Do not attach raw logs, report.json or credentials to public issues. Paid diagnosis is optional, not required to report a bug.

Similar events. Different facts.

The distinctions reliable agent metrics depend on — kept separate, each with its own evidence bar.

01

Attempt≠Operation

Attempts are execution facts. Operations are logical intents. Retries are multiple attempts of one operation, not “2 operations with 50% success.”

↓
Attempt 01 ✕
Attempt 02 ✓
↓
= 1 Operation
02

Available≠Influential

A tool result appearing in the next context proves availability. Influence — that it changed the agent's behavior — needs counterfactual evidence. Reference is a weak estimator, not a state. Unknown is a valid, first-class answer.

03

Observed≠Inferred

A selection is not a preference. A model, router, policy, workflow, or user can make it. AgentMeasure records what happened before inferring why.
