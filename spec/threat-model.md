# Threat Model（威胁模型）

> 回答：谁会攻击这套体系、怎么攻击、怎么缓解。Evidence model 的配套文档。

## 1. 攻击者画像

| 攻击者 | 动机 | 能力 |
| --- | --- | --- |
| A. 工具作者 | 刷高自己工具的 adoption 数据 | 完全控制自己工具侧；可写任意事件 |
| B. 竞争工具作者 | 贬低他人 / 制造噪音 | 同上 |
| C. 刷量产业 | 出售虚假 adoption | 批量账号、脚本、代理 |
| D. 恶意 agent/工具 | prompt injection 诱导刷量或污染 | 控制 agent 上下文 |
| E. 平台方 | 无恶意，但可能改变规则 | 平台级 |

## 2. 攻击面与缓解

| # | 攻击 | 目标层 | 缓解 |
| --- | --- | --- | --- |
| T1 | 工具作者自签 100 万条假事件（E1 合法签名） | E1 | E1 不计入 corroborated；E2 需要双边匹配（自身无法单侧伪造 trace_id 的另一侧）；行为异常检测；与独立信号（GitHub clone/npm 下载）交叉验证 |
| T2 | 工具作者 + 自己 agent 合谋（双侧伪造 E2） | E2 | 无法完全防御；缓解：身份图 + 异常检测 + 样本审计；E3（平台证明）是唯一强对抗 |
| T3 | 伪造 trace_id 冒充双边匹配 | E2 | 验签双侧事件；trace_id 需要来自 OTel 传播链（span 父子关系可验证）；时间窗约束 |
| T4 | 拆 API 刷榜（把工具拆成 50 个 tool） | Metrics | 排名按 project roll-up + Active Sessions；tool 明细不主导排名 |
| T5 | 重试刷量（失败重试链） | Metrics | session 归一 + 重试归一 |
| T6 | prompt injection 诱导 agent 调用特定工具刷量 | S1/E1 | 无直接防御；异常检测（同 session 高频单工具）；公开数据不含 prompt 无从诱导（隐私设计本身降低该风险） |
| T7 | 隐私反推（从聚合数据推断具体用户/组织） | Privacy | 最小样本量门槛；伪匿名 pid 轮换；只发布比率与计数；不做细粒度下钻 |
| T8 | 事件重放 | E1 | event_id 唯一性 + 时间窗 |
| T9 | key 泄露 | E1 | key 轮换机制；key_id 目录可撤销；泄露披露流程 |
| T10 | 聚合器被注入脏数据 | L3 | 验签 + 异常检测 + 来源信誉分（长期） |

## 3. 明确不防御的（并说明原因）

- **不防御"作者自刷 E1"**：这是设计决策——E1 只作为来源证明，不进入 corroborated 口径
- **不防御"双侧合谋"**：需要平台级证明（E3），作为升级路径而非前置
- **不做内容级审计**：隐私设计优先，宁可降低单条可验证性也不采集内容
