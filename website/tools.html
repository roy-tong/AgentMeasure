One ledger, two questions

Buyer

Did the provider charge the agreed amount? Separate invoice facts, platform usage and a rule-based recount. Keep free quota, prepaid packs, credits, tax and unlinked usage visible.

Charge review
Seller

Is metered usage fully represented in billing? Surface unpriced usage, unlinked usage and review gaps. Do not call an evidence gap “leakage revenue.”

Metering integrity
Evidence

Every source document, row, pricing policy and browser run keeps a hash, locator and audit trail. Missing evidence produces review_required, not zero.

CDP attach, not credential handoff

Some bill portals have no API. Buyer Ledger can attach to a user-started Chrome over the local DevTools Protocol, reuse the logged-in session, execute a reviewed recipe, download the bill, and push it through the same ingestion and audit pipeline.

1 · User starts Chrome

A dedicated profile opens a loopback debugging port. The user signs in and completes MFA; AgentMeasure never handles the password.

2 · Reviewed recipe runs

HTTPS and allowed hosts are checked before actions. Cross-origin navigation and downloads are blocked before they can enter the ledger.

3 · Bill is analyzed

The downloaded artifact keeps run_id, recipe hash and audit path. Parsing can be deterministic or produce a pending draft for review.

# Local Chrome must already be running with --remote-debugging-port=9222
python3 -m buyer_ledger session cdp --endpoint http://127.0.0.1:9222
python3 -m buyer_ledger fetch --recipe recipe.json --period 2026-10 --cdp http://127.0.0.1:9222 --analyze --out report.md

Security boundary: loopback only; no query tokens; any local process that can reach the debug port can control that browser. Use a dedicated profile, close it after the run, and never point this at a daily browser. Recipe actions are not a sandbox; use platform read-only roles where available.

What public billing complaints actually show

A SURE 1.6 study collected 1,949 public discovery records, read 150, and admitted 66 strict evidence records. It is exploratory: audit fails 3/12 gates, Chinese sources were unreachable, and only 3 of 18 required vendors produced admissible evidence.

The pattern

Users react strongly when paid credits expire, a spending cap fails, auto-recharge is invisible, or the usage dashboard cannot reproduce the invoice. Small amounts can still trigger chargebacks.

Ownership + visibility
For the buyer ledger

Model credits, expiry, auto-recharge, hard caps, included quota and cash billing separately. Keep a queue of unexplained charges rather than forcing them into zero.

Entitlement ledger
For the seller ledger

Check whether metered usage is represented in billing. Unpriced or unlinked usage remains an evidence gap; it is not automatically leakage revenue.

Metering integrity

Not a complaint rate, not a market validation, and not a claim about any vendor's overall conduct. A larger SURE discovery expansion now holds 50,000 unique public records (HN 49,090); strict evidence remains 66. Discovery volume is not evidence volume. Read the bounded study summary →
